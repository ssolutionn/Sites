# Game feel: реализм, который прощает

Источник правды по каждому действию — `design/gdd/interaction-spec.md`: жест, допуски, отклик, текст ошибки, статус.
Этот навык — правила, которые нельзя нарушать при правке кода.

## 1. Железное правило

- Всё, что героиня делает руками на кухне, игрок делает **движением мыши**: нажал → повёл → отпустил.
- Кнопка вместо жеста допустима только для мета-интерфейса: телефон, меню, выбор задачи в списке, подтверждение блюда, пауза, «Переделать».
- Если жест пока не построен, кнопку можно оставить, но в спецификации у действия должен стоять 🔧 или 🆕. Новую кнопку для физического действия не добавлять.
- Таймер «нажал и жди 1,2 с» (`_startAction` без жеста) — это клик, а не жест. Длительность допустима только как анимация **после** распознанного жеста.

## 2. Как распознавать жест

1. **Классифицируй форму, а не точку.** Ось — методом главных компонент (`Stroke.axis()`), а не «первая точка → последняя». Круги — накопленным углом (`Stirrer`), тряска — полными циклами (`ShakeTracker`), налив — путём над целью (`PourTracker`), мазки — маской покрытия (`CoverageMask`).
2. **Прощай в пределах допуска.** Кривая, но понятная линия засчитывается и выпрямляется. Отказывай только за пределами допуска.
3. **Объясняй отказ.** У каждой причины есть код (`reason`) и фраза в словаре подсказок (как `CUT_HINTS`). Причина без фразы — баг.
4. **Не наказывай за распознавание.** Отказ не тратит продукт, качество и игровое время. Штраф бывает только за кулинарный промах: пересол, перебор, недорез.
5. **Прогресс не сгорает.** Отпустил кнопку посреди тёрки, мешания или мытья — прогресс сохранился. Курсор ушёл за окно — это обычное отпускание (`pointerUp()`).
6. **Метры, не пиксели.** Все пороги в локальных метрах станции (доска — в u = `BOARD_UNIT`), скорость — в u/с или м/с. Тогда пороги не зависят от DPI и размера окна.
7. **Числа — в данных.** Допуски живут в `CAMPAIGN` (`src/campaign/data.js`), а не в коде станции. Логика жеста — чистый модуль без DOM и Three.js, его можно проверить в `node:test`.
8. **Продукт может отличаться.** Особенности продукта (яйцо скользит, хлеб пилят, лук катается, сыр плотный) — это параметры профиля, а не отдельная ветка кода на каждый продукт.
9. **Мягкий режим.** Доступность — это множитель допусков `assist.k` (1,5), а не замена жеста кнопкой.

### Допуски по умолчанию

| Что | Значение |
|---|---|
| Угол ножа от вертикали или горизонтали | ≤ 28° |
| Дрожь (путь / хорда) | ≤ 1,9 |
| Минимальная длина росчерка | 0,6 u (короче — молча игнорировать) |
| Режется кусок, если лезвие прошло | ≥ 60 % его хорды |
| Радиус ловли при переносе | ×1,2 от видимого |
| Тряска: размах / интервал | ≥ 0,025 м / ≥ 0,18 с |
| Круги: рывок / угол за шаг | ≤ 0,09 м / ≤ 1,2 рад |

## 3. Отклик в четыре слоя

Каждое засчитанное движение даёт **минимум два слоя**, а итог операции — все четыре:

1. **Объект меняется.** Кусок отделяется, слой виден по маске, пакет сминается, стружка растёт, кожура отгибается. Это главный слой: игрок должен видеть результат на самом продукте.
2. **Звук.** Каждое событие жеста есть в `SOUND_OF` (`src/main.js`). Отказ — мягкий `deny`, а не тишина. Непрерывный жест — тик на каждые 15–25 % прогресса, а не сплошной гул.
3. **Частицы.** Крошки цвета продукта (`PRODUCTS[*].color`), капли сока, соль, брызги. 4–16 штук, жизнь 0,5–1,2 с.
4. **Импульс.** Небольшой толчок камеры (≤ 1,5 см, 120 мс) на ударе ножа или прокола, пульс счётчика или полосы прогресса. Без тряски экрана на рутинных действиях.

### Тайминги

| Момент | Норма |
|---|---|
| Отклик на нажатие (подсветка, просадка) | ≤ 100 мс |
| Результат дискретного жеста (удар ножа) | 0,15–0,25 с (`knifeDuration` 0,22) |
| Подсказка после отказа | ≤ 150 мс после отпускания |
| Время показа подсказки | 2–2,5 с, одна и та же — не чаще раза в 1,2 с |
| «Призрак» правильного жеста | после 3 одинаковых отказов за 20 с, длится 1,5 с |
| Подсказка «стоишь на месте» в непрерывном жесте | через 1,5 с без прогресса |
| Длина одной операции | 2–6 с: дольше — скучно, короче — не успеваешь почувствовать |

## 4. Тексты ошибок

- На «ты», ≤ 70 символов, два шага: «что случилось — как исправить». Пример: «Хлеб мнётся — пили ножом туда-обратно».
- Без слов «ошибка», «неверно», «неправильный ввод». Без упрёка и без канцелярита.
- Говорить о продукте и руке, а не об интерфейсе: «веди нож», а не «проведи курсор».
- Текст совпадает с тем, что сказано в уроке (`src/campaign/lessons.js`, поле `mistake`), если речь о той же ошибке.

## 5. Тесты

- На каждый жест — юнит-тест на синтетической траектории: эталон засчитан; ровно на границе допуска засчитан; граница + 10 % отклонена с правильным `reason`.
- Тесты детерминированы: точки и время задаются фабрикой, без `Math.random` и реального времени.
- Браузерный сценарий (`scripts/*.mjs`) проходит действие жестом через `page.mouse.down/move/up`, а не вызовом метода сессии. Скриншот результата кладётся в `production/qa/evidence/`.

## 6. Чек-лист перед слиянием любого взаимодействия

- [ ] Действие выполняется нажатием, движением и отпусканием. Новых кнопок для физических действий нет.
- [ ] Жест описан в `design/gdd/interaction-spec.md`, статус обновлён (✅/🔧/🆕).
- [ ] Пороги в `CAMPAIGN`, единицы — метры или u, не пиксели.
- [ ] У каждой причины отказа есть фраза, звук `deny` и нет траты ресурса.
- [ ] Отпускание посреди жеста и уход курсора за окно не ломают состояние и не съедают прогресс.
- [ ] Минимум два слоя отклика на событие, четыре — на завершение. События есть в `SOUND_OF` и в `view.onEvent`.
- [ ] Тайминги в пределах таблицы из раздела 3.
- [ ] Юнит-тесты на эталон, границу и границу + 10 % проходят (`npm test`).
- [ ] Действие пройдено вживую мышью и тачпадом, скриншот лежит в `production/qa/evidence/`.
- [ ] Текст `how` в уроке описывает то же движение, что и жест.
