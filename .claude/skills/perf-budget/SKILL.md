# Бюджет производительности

Цель: 60 кадров на ноутбуке со встроенной графикой (Intel Iris Xe / Apple M1) при
1920×1080 на `high` и стабильные 30+ на слабом ПК на `low`. Программный рендер
(SwiftShader, контейнер) годится для **счёта** вызовов и треугольников, но не для FPS.

удваивает их (489 против 305), а в сцене 628 отдельных сеток при всего 2 `InstancedMesh`
с нулевым `count`.

## Как мерить

```bash
npx vite build                         # размеры чанков печатает сама сборка
du -sh dist dist/models dist/assets
npx vite preview --port 4174 --strictPort &
```

- Быстро глазами: `http://localhost:4174/?dev` — в панели DEV строка
  «FPS · вызовов · треуг. · геом. · текст.» (обновляется раз в секунду).
- Скриптом (Playwright, SwiftShader): войти на кухню, дождаться двух
  `requestAnimationFrame`, прочитать `window.__sueta.sv.renderer.info.render.calls`,
  `.triangles`, `.memory`, `.programs.length`; обойти `sv.scene.traverse` и сложить
  `width × height × 4 × 1,33` уникальных текстур; тени — `sv.sun.shadow.mapSize`.
- `renderer.info.render` сбрасывается на каждый `render()`, проход теней входит в счёт.
- FPS — только на настоящей видеокарте и в Electron-сборке (`npm run desktop`).

## Что делать, чтобы уложиться

1. **Инстансинг повторов**: кусочки нарезки, крошки, горошек, банки на полках,
   плитка, огоньки гирлянды, снежинки — один `InstancedMesh` на вид предмета;
   матрицы обновлять только у изменившихся экземпляров, `count` держать точным.
2. **Слияние статики**: мебель и декор, которые не двигаются, — `mergeStaticMeshes`
   (`src/view/model-utils.js`) по материалу; цель — ≤ 1 вызова на материал статики.
3. **Тени**: отбрасывают только героиня, кот, кастрюли и продукты в кадре
   (`castShadow` у мелочи выключен); стены и пол — только `receiveShadow`;
   `shadow.autoUpdate = false` для статики и `needsUpdate` при движении.
4. **Атласы текстур**: процедурные текстуры (`src/view/textures.js`) одного стиля —
   в один атлас 2048² вместо десятка мелких; `CanvasTexture` создавать один раз.
5. **Ленивая загрузка GLB по дням**: модели дня грузятся на карточке дня, а не при
   старте; меню и день 1 не ждут моделей дней 2–7; освобождать `dispose()` при смене дня.
6. **Сжатие GLB**: meshopt или Draco для геометрии, KTX2 для текстур; ≤ 1,5 МБ на модель.
7. **Частицы**: пар, пузыри, крошки — пул фиксированного размера, без создания
   объектов в кадре.

## Переключатель качества (`applyQuality` в `src/main.js`)

Сейчас `save.data.settings.quality`:
- `high` — `setPixelRatio(min(devicePixelRatio, 2))`, тени включены (`shadowMap.enabled`, `sun.castShadow`);
- `low` — `setPixelRatio(1)`, тени выключены.

Что добавить для `low` (и проверить, что `high` не теряет вида):
- карта теней 1024² на `high` для встроенной графики, тени выключены на `low` (как сейчас);
- DPR на `high` ограничить 1,5 на экранах 4K; на `low` — 1;
- частиц вдвое меньше, крошки нарезки без физики;
- без окружения PMREM и постобработки (когда появятся);
- упрощённые материалы (`MeshLambertMaterial`) для дальнего декора;
- сегменты продуктов и кусочков — половина от `high`.

Переключение не должно пересоздавать шейдеры каждый раз: после смены качества
число программ растёт (27 → 37) — допустимо один раз, не при каждом нажатии.
