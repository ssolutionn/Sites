# Общие правила для параллельных агентов 0.11 (читать первым)

Проект: «Симулятор новогодней суеты» (three.js 0.186, Vite 8, Electron, JS без TypeScript), коммерческий релиз в Steam,
партнёр «Пятёрочка». Владелец работает в киберспорте и эфирах, пишет коротко, просит естественный русский без канцелярита.
Подробности и слова владельца — `docs/HANDOFF_v011_ChatGPT.md` (раздел 0 и твой блок). Из этого файла **игнорируй** 0.1
(ветки): ты работаешь в своей рабочей копии (git worktree) на своей ветке, ничего никуда не пушишь.

## Git
- Коммить только в своей ветке рабочей копии. **`git push` не делать.** Слияние выполнит Claude.
- Формат: Conventional Commits по-русски (`feat:`, `fix:`, `test:`, `docs:`, `refactor:`), в теле — что и зачем, как проверено,
  строка `Task: 0.11 <твоя задача>`. Последние две строки сообщения ровно такие:
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` и `Claude-Session: https://claude.ai/code/session_01FGx6tw6oGSPKftvX4UAwQf`
- Запрещено: `git push` любой, `git reset --hard`, `git clean -f…`, `rm -rf`, `sudo`, `chmod 777`, чтение и запись `.env*`,
  переписывание истории. Не удалять файлы, которые не создавал сам.
- Не вписывай в файлы репозитория, коммиты и тексты названия моделей ИИ и имена ассистентов.

## Рабочая копия
```
ln -s /home/user/Sites/node_modules node_modules      # один раз, зависимости общие
npm test                                              # node:test, ~5 с, должно быть зелёным до и после
npx vite build                                        # быстрая сборка без синхронизации моделей
npx vite preview --port <ТВОЙ_ПОРТ> --strictPort --host 127.0.0.1    # в фоне (run_in_background), потом остановить по PID
PW=/opt/node-tools/node_modules/playwright/index.mjs OUT=production/qa/evidence node scripts/<твой-скрипт>.mjs http://127.0.0.1:<порт>/ all
```
- Браузер в облаке рисует через SwiftShader — медленно. Снимок: `page.screenshot({ timeout: 150000 })`. После смены камеры жди
  `window.__sueta.sv.camMode === '<режим>' && sv.camT >= 1`, а не паузу. Образцы: `scripts/v10-shots.mjs`, `scripts/campaign-e2e.mjs`.
- Останавливай свои фоновые процессы по PID. Не используй `pkill -f` и общие шаблоны: рядом работают другие агенты.
- Эталон вида кода: рядом лежащие файлы. Комментарии плотные, как в соседях, по-русски. Доки на публичные API — коротко.

## Жёсткие правила проекта
- **Бренд «Пятёрочки»** в обычной сборке не трогать (логотип, «Пятёрочка Доставка», «Выручай-карта», значок, магнит).
  Новые брендовые тексты — через проверку нейтральной сборки (константа `SHOP` в `src/ui/phone.js`, `NEUTRAL`).
  Нейтральная сборка (`VITE_NEUTRAL=1`) обязана оставаться чистой: `node scripts/check-neutral.mjs <папка>`.
- **GLB или процедурные героиня и кот** — не менять, ждёт решения владельца.
- **Руками, а не кнопками** (навык `.claude/skills/game-feel`). Физическое действие = жест мышью. Кнопка — только мета-интерфейс.
- **Числа — в `CAMPAIGN`** (`src/campaign/data.js`), ключи добавляй рядом с родственными, не в конец объекта. Логика — в чистых
  модулях без DOM и Three.js. UI меняет состояние только через `act(...)`. DOM обновляй по изменению (`_sig`, `_set`).
- **Тесты**: новый жест — эталон, ровно граница допуска, граница+10 % (отказ с правильной причиной). Исправленный баг —
  регрессионный тест, который ты видел красным. Без `Math.random` и реального времени (у сессии `this.rng`). Файлы тестов
  называй уникально по задаче (`tests/<тема>-v11.test.js`).
- **Интерфейс**: стекло и токены `src/ui/theme.css`, шрифт ≥ 12,5 px, одна главная кнопка, без английских подписей и без
  отладочных панелей вне `?dev`. Тексты на «ты», тепло; отказ — «что случилось — как исправить», ≤ 70 знаков, без «ошибка/неверно».
  Навыки: `.claude/skills/game-ui-ux`, `game-feel`, `browser-visual-qa`.
- **Видимое изменение** → снимок мышью через Playwright в `production/qa/evidence/v11_<тема>_*.png` и проверь его глазами (Read).

## Как не мешать другим (параллельно правятся session.js, data.js, campaign-ui.js, campaign-view.js, kitchen.js, main.js,
st-*.js, theme.css, phone.js)
- Новую логику и модели — в **новые файлы**. В общих файлах правь минимально и точечно: не переформатируй, не переноси,
  не сортируй, не переименовывай чужое.
- Не правь `CHANGELOG.md`, `docs/QA_*.md`, `design/gdd/interaction-spec.md`, версию в `package.json` и `CAMPAIGN.version`.
  Вместо этого напиши заметки в `.planning/2026-10-12-agents/<твоё-имя>.md`: что сделано, решения, как проверить, какие строки
  добавить в спецификацию (жест, допуск, отказ, статус).
- Свой скрипт проверки назови `scripts/v11-<имя>-shots.mjs` (код выхода 1 при провале).

## Финальный отчёт (≤ 350 слов, на русском)
Ветка и последний коммит; список созданных/изменённых файлов; тесты (сколько добавлено, итог `npm test`); что проверено в
браузере, где лежат снимки; принятые решения и отступления от задания; что НЕ сделано и почему; места, где возможен конфликт
при слиянии с другими.
