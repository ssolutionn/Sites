# Контракт на 3D-ассеты (GLB)

Версия 1.0 · 2026-10-08 · отвечает арт-директор, техническая часть — технический художник.
Как модель должна выглядеть — `design/art/art-bible.md`. Здесь — как файл должен быть устроен,
чтобы игра на three.js 0.186 подхватила его без правок в Blender. Короткий чек-лист для работы —
скилл `.claude/skills/asset-pipeline/SKILL.md`.

## 1. Где лежат файлы

```
assets/                              исходники художника (в git)
  characters/girl/   girl.blend, girl.glb, girl_idle.glb, girl_walk.glb, …, textures/
  characters/cat/    cat.blend, cat.glb, cat_*.glb, textures/
  food/  kitchen/  props/            <asset>.blend, <asset>.glb, textures/
public/assets/models/                то, что грузит игра (копия, руками не трогать)
  characters/girl/girl.glb …
  manifest.json
```

- Художник работает только в `assets/`: кладёт `.blend` и рядом экспортированный `.glb`.
- В игру файлы попадают через скрипт `scripts/sync-models.mjs` (команда `npm run models:sync`, повесить
  на `predev` и `prebuild`). Скрипт копирует только `.glb` с сохранением путей, проверяет их (раздел 11)
  и пишет `manifest.json`. Позже здесь же будет сжатие (раздел 10). Скрипта пока нет — его пишет
  tools-programmer; до тех пор копируем вручную и сами правим `manifest.json`.
- Почему так: Vite отдаёт `public/` как есть, а `.blend` и исходные текстуры не должны попасть в `dist/`
  и в сборку Electron. Сжатие делается в одном месте, исходники остаются несжатыми.
- Git: `.blend`, `.glb`, `.png`, `.jpg` в `assets/` хранить через Git LFS (нужен `.gitattributes`).
  Когда скрипт появится, `public/assets/models/` добавить в `.gitignore` — это сгенерированная копия.
- URL в игре: `./assets/models/<путь>.glb` — относительный, работает и в вебе (`base: './'`),
  и в Electron (`file://`).
- Старые `public/models/heroine.glb` и `cat.glb` — выгрузка процедурных моделей
  (`scripts/export-models.mjs`): иерархия частей без скелета и весов. В этот контракт они не входят,
  основой для рига не служат (ТЗ 6.1). Живут до замены, пока ими пользуется галерея.

## 2. Единицы, оси, масштаб

- 1 единица = 1 метр. В Blender: Unit System Metric, Unit Scale 1.0, Length — метры.
- Экспорт с флагом **+Y Up**. Вправо — +X.
- **Вперёд — +Z glTF.** В Blender персонаж смотрит в камеру в виде Front (Numpad 1), то есть по −Y;
  после экспорта это +Z. Так ждёт код: `LAYOUT` — «facing 0 — лицом к камере (+Z)», лицо в
  `heroine.js` и морда в `cat.js` смотрят в +Z, поворот считается как `atan2(dx, dz)`.
- Перед экспортом: Apply All Transforms на мешах; у корневого объекта и арматуры location 0,
  rotation 0, scale 1. Отрицательный scale запрещён.
- Масштаб проверять рядом с эталоном: бокс 1.65 м (рост героини) и плоскость на 0.90 м (столешница).

## 3. Точка опоры (pivot) и ориентация

| Класс | Pivot | Ориентация |
|---|---|---|
| Героиня | между стоп, на полу (y = 0) | лицом в +Z |
| Кот | под центром корпуса между лапами, на полу | мордой в +Z |
| Реквизит на поверхности (миска, кастрюля, банки, тарелки, доска) | центр дна, y = 0 — плоскость касания | ручка или этикетка к +Z; доска длинной стороной по X |
| Мебель | центр основания, на полу | фасад к +Z |
| Дверцы, створки | на оси петли; закрытое положение — rotation 0 | открывание в коде |
| Съёмные части (крышка кастрюли) | отдельный узел, pivot в центре низа детали | стоит на своём месте в GLB |
| Нож | на режущей кромке, у середины лезвия | лезвие в плоскости YZ, остриё в −Z, рукоять в +Z, кромка вниз (−Y) |
| Телефон | центр задней грани | лежит экраном вверх (+Y), верх экрана к −Z |

Ручной реквизит с pivot не в точке хвата (нож, телефон, ложка) содержит пустой узел `grip` в точке
хвата: код совмещает `grip` с сокетом руки (раздел 7).

Игровые размеры (верх острова 0.90, доска 0.60 × 0.40 × 0.03 и т. д.) — в арт-библии, раздел 5.
Модель, которая в них не попадает, не принимается.

## 4. Имена

- `snake_case`, только ASCII, без пробелов и точек. GLTFLoader вырезает из имён узлов `.`, `:`, `[`, `]`
  и пробелы — после этого поиск узлов и анимации по именам ломаются.
- Файлы: `<asset>.glb`; клип отдельным файлом — `<asset>_<clip>.glb`; LOD — `<asset>_lod1.glb`;
  исходник — `<asset>.blend`. Категория задаётся папкой, в имени файла её нет.
- Корневой узел внутри GLB — с префиксом категории: `char_girl`, `char_cat`, `kit_island`,
  `prop_knife`, `food_carrot`.
- Материалы: `m_<asset>_<часть>` (`m_girl_skin`, `m_girl_knit`); логотип — всегда `m_brand_logo`.
- Текстуры: `<asset>_basecolor.png`, `_orm.png`, `_normal.png`, `_emissive.png`.
- Кости: `root`, `hips`, `spine_01…03`, `neck`, `head`, `upper_arm_l`, `forearm_r`, `hand_l`, `thigh_r` …
  Сторона — суффикс `_l` / `_r`.
- Сокеты: `socket_hand_r` (нож, ложка), `socket_hand_l` (телефон), у кота `socket_mouth` (колбаса).
- Подвижные узлы, которые ищет код: `lid`, `door`, `screen`, `led`, `dial`, `water`, `foam`, `bulb_00`…`bulb_17`.
- Shape keys героини: `blink`, `smile`, `worried`, `mouth_o`; кота: `blink`, `mouth_open`.

## 5. Материалы

- Только Principled BSDF: другие узлы в glTF не экспортируются. Используем Base Color, Metallic,
  Roughness, Normal (через Normal Map), Emission со Strength, Alpha; Sheen — только свитер героини.
- Base Color и Emission — sRGB. ORM (R — AO, G — Roughness, B — Metallic) и Normal — Non-Color.
  Normal map в формате OpenGL (Y+), как в Blender; карты DirectX — с инвертированным G.
- Цвета берутся из палитры арт-библии: hex вводится в поле Hex в Blender, перевод в линейное он делает сам.
- Без текстуры — можно: плоский Base Color из палитры. Текстура — когда есть рисунок.
- Размер текстур: 2048 — героиня и кот, 1024 — мебель и главный реквизит, 512 — мелочь и еда.
  Стороны — степени двойки.
- Alpha: по умолчанию Opaque; Alpha Clip — для вырезов; Alpha Blend — только стекло.
  Transmission не используем: это отдельный проход рендера.
- Вершинные цвета не экспортируем, если материал их не использует.
- Логотип — отдельный материал `m_brand_logo` со своей текстурой (нейтральная сборка подменяет его).

## 6. Бюджеты

| Класс | Треугольники | Текстура | Материалы | Кости | Размер GLB |
|---|---|---|---|---|---|
| Героиня | ≤ 30 000 | 2048 | ≤ 4 | ≤ 60 | ≤ 8 МБ |
| Кот | ≤ 15 000 | 2048 | ≤ 3 | ≤ 40 | ≤ 4 МБ |
| Комната (стены, пол, окно) | ≤ 10 000 | 1024 | ≤ 3 | — | ≤ 4 МБ |
| Предмет мебели | ≤ 8 000 | 1024 | ≤ 2 | — | ≤ 2 МБ |
| Главный реквизит (нож, доска, миска, кастрюля, телефон) | ≤ 3 000 | 1024 | ≤ 2 | — | ≤ 1 МБ |
| Мелкий реквизит, цельные продукты | ≤ 1 000 | 512 | 1 | — | ≤ 300 КБ |

Вся сцена — не больше 250 000 треугольников и 150 draw calls. Для сравнения: процедурная героиня
сейчас около 74 000 треугольников, кот около 32 000 (`docs/model-stats.json`) — GLB должны быть легче.

## 7. Риг и скиннинг

- Одна арматура на персонажа, объект `rig`; корневая кость `root` в начале координат, `hips` — её потомок.
- Не больше 4 влияний на вершину, веса нормализованы (в экспортёре Bone Influences = 4).
  Пятое влияние three.js молча отбрасывает.
- Героиня — не больше 60 деформирующих костей, кот — не больше 40. Управляющие и IK-кости не
  экспортируются (только деформирующие).
- Ориентир для героини: root, hips, spine ×3, neck, head, плечо, плечевая кость, предплечье, кисть ×2,
  пальцы (большой ×3, остальные ×2) ×2, бедро, голень, стопа, носок ×2, 2–4 кости на пучок и фартук.
  Для кота: root, hips, spine ×3, neck ×2, head, jaw, уши ×2, хвост ×6, лапы 4 × 4.
- Поза покоя: героиня — A-поза (руки под 45°), кот — стоит на четырёх лапах.
- Сокеты — пустышки или кости, привязанные к `hand_r`, `hand_l`, `head`. Начало сокета — точка хвата,
  оси сокета совпадают с осями `grip` предмета.
- Мимика — shape keys на меше головы, не больше 8.
- Root motion нет: клип играется на месте, перемещает персонажа игра. Кость `root` в клипах не двигается по XZ.

## 8. Анимации

- 30 fps. Имя клипа = имя Action в Blender, строчными, как в таблице.
- Зацикленные клипы: первый кадр совпадает с последним. Одноразовые заканчиваются в позе, которую
  можно держать.
- Основной вариант: все клипы внутри `girl.glb` / `cat.glb` (экспорт всех Actions арматуры). Допустим
  и вариант с отдельными `girl_<clip>.glb` — только с той же арматурой и теми же именами костей, без меша.
- Ходьба: героиня ходит со скоростью 2.2 м/с (`walkSpeed` в `src/campaign/data.js`), кот 1.6–1.8 м/с,
  убегает 2.6 м/с. Длину шага в клипе подбирать под эти скорости, чтобы ноги не скользили.
- Моменты внутри клипа (касание, удар) в glTF не экспортируются. Их записываем в файл
  `<asset>.clips.json` рядом с `.blend`: `{ "knock_over": { "contact": 0.55 } }`. Скрипт переносит их в манифест.

| Героиня | Тип | Длительность | Что важно |
|---|---|---|---|
| `idle` | цикл | 2–4 с | дыхание, лёгкое покачивание |
| `walk` | цикл | 0.6 с (18 кадров) | торопливый шаг, 1.32 м за цикл = 2.2 м/с |
| `cut` | один удар | 0.5–0.7 с | нож в `socket_hand_r`; игра проматывает клип по прогрессу разреза |
| `stir` | цикл | 1.0 с | ложка в `socket_hand_r` |
| `open_fridge` | разовый | 1.0–1.5 с | заканчивается рукой на двери |
| `phone_answer` | разовый → держать | 0.8 с | телефон в `socket_hand_l`, держит у уха |
| `taste` | разовый | 1.5 с | ложка ко рту |
| `carry` | цикл, верх тела | 1.0 с | руки впереди с ношей; играется вместе с `walk` |
| `shoo` | цикл | 0.5 с | машет руками на кота |
| `celebrate` | разовый → цикл | 2 с | радость на финале |

Желательно добавить (под позы, которые уже есть в коде): `work`, `grate`, `wash`, `wipe`, `unpack`,
`stove`, `reach_up` (гирлянда). Пока их нет, код берёт ближайший клип по таблице из скилла
`character-animation`.

| Кот | Тип | Длительность | Что важно |
|---|---|---|---|
| `idle` | цикл | 2–3 с | хвост, уши |
| `walk` | цикл | 0.45 с | на месте |
| `sit` | цикл | 3 с | сидит, смотрит |
| `sleep` | цикл | 4 с | свернулся, дышит |
| `steal_run` | цикл | 0.4 с | бег, колбаса в `socket_mouth` |
| `knock_over` | разовый | около 1.2 с | лапой сбивает стакан; момент касания — в `cat.clips.json` |
| `eat` | цикл | 1.0 с | голова в миске |
| `meow` | разовый | 0.8 с | shape key `mouth_open` |

Желательно: `jump_up` (на столешницу 0.90 м, около 0.35 с), `reach` (тянется лапой за колбасой).

## 9. LOD

В первой версии LOD не делаем: одна комната, два персонажа. `_lod1` (около 50 % треугольников)
добавляется, только если профилирование покажет упор в вершины.

## 10. Сжатие

- **Сейчас:** экспорт без сжатия. Декодеры Draco, meshopt и KTX2 в игре не подключены: сжатый GLB
  не загрузится вообще (GLTFLoader падает с ошибкой про отсутствующий декодер).
- **Потом:** сжатие делает скрипт синхронизации через glTF-Transform — meshopt для геометрии,
  анимаций и shape keys, KTX2 для текстур. Исходники в `assets/` остаются несжатыми.
  В загрузчике тогда понадобятся `setMeshoptDecoder` и `KTX2Loader`. Meshopt лучше Draco:
  сжимает и анимацию, а распаковывается быстрее.

## 11. Проверка перед сдачей

1. `npx @gltf-transform/cli validate <file>.glb` — ноль ошибок; предупреждения перечислить в сдаче.
2. `npx @gltf-transform/cli inspect <file>.glb` — треугольники, материалы, размеры текстур в рамках раздела 6.
3. three.js editor (https://threejs.org/editor/), перетащить файл: модель стоит, смотрит в +Z, размер верный,
   клипы проигрываются, имена узлов без точек.
4. В игре: скриншоты в общем плане и в крупном плане при игровом свете, файлы
   `production/qa/evidence/model_<asset>_<ГГГГ-ММ-ДД>_<вид>.png`. Без скриншота модель не принята.
5. Сравнение с процедурной версией: тот же кадр с `?procedural=1`.

Шаг, который не удалось выполнить, в сдаче так и называется: `НЕ ПРОВЕРЕНО: <шаг> — <причина>`.
Невыполненная проверка не считается пройденной.

## 12. Как игра загружает модели

Этот слой пишет программист; здесь — договорённость, на которую опирается художник.

- `public/assets/models/manifest.json` (пишет скрипт синхронизации):
  `{ "version": 1, "models": { "girl": { "url": "characters/girl/girl.glb", "clips": [], "markers": {} } } }`.
- Новый модуль `src/view/assets.js`: `loadManifest()` и `loadModel(id)` → `{ scene, animations }` или `null`.
  GLTFLoader, кэш по id. Нет записи в манифесте или ошибка загрузки — `null` и предупреждение в консоли
  с именем файла.
- Модели грузятся при запуске, до первого кадра, под экраном загрузки. Во время игры модели не подменяются.
- **Запасной вариант:** если `loadModel` вернул `null`, работает текущий процедурный конструктор
  (`buildHeroine`, `buildCat`, `buildKitchen`). Игра полностью играбельна без единого GLB.
  В сцене всегда одна героиня и один кот — GLB либо процедурная модель, не обе сразу (ТЗ 6.1).
- Интерфейс персонажей не меняется: `animateHeroine(h, pose, time, progress)`, `setExpression(h, worried)`,
  `animateCat(cat, mode, time, speed)` и ключи `userData` (`knife`, `phoneProp`, `loot`). Для GLB внутри
  ветка по `userData.rig === 'gltf'` (подробно — скилл `character-animation`).
- Подвижные части код двигает относительно позиции покоя из GLB. Сейчас в `scene.js` написано
  `pot.lid.position.y = 0.21` — для GLB эту позицию нужно запоминать при загрузке.
- Всем мешам — `castShadow` и `receiveShadow`; полу и стенам — только `receiveShadow`.
- Копии персонажей со скелетом — только через `SkeletonUtils.clone`.
- `?procedural=1` принудительно включает процедурные модели. При запуске в консоль пишется одна строка:
  какие модели пришли из GLB, какие процедурные — пропуск должен быть виден.
- Галерея (`gallery.html`) грузит модели тем же модулем: в игре и галерее одна версия ресурсов (ТЗ 6.5).
