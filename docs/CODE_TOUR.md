Для внешнего ревьюера, который открывает репозиторий впервые. Репозиторий: https://github.com/ssolutionn/Sites,
ветка `claude/technical-specification-mx99wl`, версия `0.7.1` (`package.json`). Написано по коду на 2026-10-09;
номера строк не приводятся, потому что код быстро меняется: ориентируйтесь на имена файлов и функций.

Рядом: `docs/CHATGPT_BRIEF.md` — что за проект, правила и готовые запросы для ревьюера; `docs/IMPROVEMENTS.md` —
наш собственный план улучшений до релиза. Пакет одним файлом и архивом собирает `node scripts/review-bundle.mjs`.

## 1. Что это за игра и как её запустить

- Кухонный симулятор на семь дней перед Новым годом (25–31 декабря): десять блюд — от оливье до запечённой курицы — и финальный праздничный стол.
- Героиня ходит по 3D-кухне между станциями: доска, миска, плита, раковина, поднос, духовка, радио, телефон. Всё делается мышью «как в жизни»: нож режет там, где прошёл, ложкой мешают по кругу, солонку трясут, огонь регулируют крутилкой.
- Параллельно идут помехи: кастрюля убегает, кот тянется к колбасе, радио ломается, курьер везёт недостающие продукты, гости пишут пожелания.
- За каждое блюдо и за день ставится оценка, даются звёзды и медали. Прогресс хранится в `localStorage`.
- Цель — релиз в Steam через Electron-обёртку (macOS, Windows). Есть партнёрская сборка с брендом «Пятёрочки» и нейтральная, без бренда.

Нужен Node.js 20.19 или новее. Стек: three.js 0.186.1, Vite 8, обычные ES-модули без TypeScript.

| Команда | Что делает |
|---|---|
| `npm install` | ставит three, vite, electron, @electron/packager |
| `npm run dev` | dev-сервер Vite, сам откроет браузер (обычно http://localhost:5173) |
| `npm test` | `node --test tests/*.test.js` — около 150 тестов логики (сейчас 154), примерно 2 с, без браузера |
| `npm run pacing` | `scripts/pacing-sim.mjs`: проходит все 7 дней через API сессии с допущениями о темпе игрока и печатает время по дням. Сейчас кампания занимает ≈45 мин у уверенного игрока и ≈59 мин при первом прохождении |
| `npx vite build` (= `npm run build`) | сборка в `dist/` из трёх страниц: `index.html` (кампания), `classic.html` (старый режим «Оливье за 5 минут» из 0.3.1), `gallery.html` (3D-галерея героини и кота). Открывать через `npx vite preview`, а не двойным щелчком |
| `npm run desktop` | собрать и сразу открыть в Electron: `desktop/main.cjs` отдаёт `dist/` по своему протоколу `app://` |
| `npm run desktop:mac` / `npm run desktop:win` | упаковка через `desktop/build.mjs` в `build/desktop-out/`. То же самое делает CI `.github/workflows/desktop-build.yml` на каждый push |
| `npm run calibrate` | `scripts/calibrate-trims.mjs` — подбор допуска краевых обрезков (см. п. 5) |
| `npm run export:models` | выгружает процедурных героиню и кота в `public/models/*.glb` |

Браузерные сценарии `scripts/*.mjs` работают через Playwright, которого **нет в `package.json`**. Поставьте его отдельно
(`npm i -D playwright && npx playwright install chromium`) или укажите путь в переменной `PW`. Пример:
`npx vite build && npx vite preview --port 4173`, затем `node scripts/campaign-e2e.mjs http://localhost:4173/ d1`.

Флаги:
- `?dev` — панель «FPS · вызовы отрисовки · треугольники · геометрии · текстуры» (данные из `renderer.info`), кнопки «Завершить день (авто)», «Кот к колбасе», «Выкипание», «+30 с», «Открыть все дни» и ссылки на `classic.html` и `gallery.html` в меню.
- `?seed=N` — фиксирует случайность дня: окна помех, скрытую «норму» соли, пожелания гостей, ожидание курьера (`createRng` из `src/game/rng.js`). Без флага зерно случайное.
- `VITE_NEUTRAL=1 npx vite build` — сборка без бренда. В `src/view/textures.js` `NEUTRAL` — сравнение со строкой `'1'`/`'true'` (сборщик подставляет значение и вырезает брендовые ветки), плагин `neutralBrand` в `vite.config.js` меняет иконку вкладки и не кладёт `logo-5.svg` в сборку. Флаг меняет логотип на `public/assets/logo-neutral.svg`, убирает подпись «вместе с «Пятёрочкой»» в меню (`campaign-ui.js`), а в телефоне превращает приложение «Пятёрочка» в «Доставку» и «Выручай-карту» — в «Бонусную карту» (`phone.js`). Публичные ссылки по решению владельца делаются только с нейтральной сборки.
- Electron: `SUETA_SMOKE=out.png` запускает самопроверку — через 8 с делает снимок окна, выводит ошибки консоли и закрывается.
- В консоли браузера всегда доступен `window.__sueta` (`session`, `mode`, `sv`, `view`, `app`, `save`, `radio`). Через него работают e2e-сценарии.

### `src/game/` — ядро 0.3.1 и нож
- `raster-cut.js` — **нож, которым режет игра**. `CutBody` — продукт как маска клеток по 1 мм (`CELL = 0.1` при единице 1 см). `cutSegment(a, b)` разрывает связи между клетками, через которые прошло лезвие. `pieces()` находит куски как связные области (заливкой) и считает их площадь и вытянутость. `contour()` строит контур куска для 3D, `sweep()` убирает крошки, `removePiece`/`addPattern` нужны для кражи котом и замены. `rasterQuality()` оценивает кубики.
- `cutting.js` — **старая полигональная нарезка**: куски — прямоугольники или выпуклые многоугольники, разрез — линией (`cutAcross`, `cutLine`). Целиком её использует только классический режим (`classic-main.js`, `game.js`, `ui/ui.js`, `view/board.js`). Кампания берёт из неё лишь вспомогательные `bounds`, `pieceVolume` и `largestPiece`. Ещё её используют `scripts/calibrate-trims.mjs` и тесты `cutting-v03`, `logic`, `gestures`. Ни один день кампании через неё уже не режет — подробнее в п. 5.
- `game.js`, `layout.js` (`LAYOUT`), `scoring.js` — режим «Оливье за 5 минут». `rng.js` — генератор mulberry32 с фиксируемым зерном.

### `src/view/` — three.js (только читает сессию)
- `scene.js` — `SceneView`: рендерер (ACES, тени PCFSoft с картой 2048², окружение PMREM RoomEnvironment), свет, камеры, кухня, героиня, кот. Исторически это сцена классического режима; кампания надстраивается поверх неё.
- `campaign-view.js` — `CampaignView` (≈1,7 тыс. строк): камеры станций и крупные планы, выбор мышью (`pick`, `pickLocal` переводит курсор в локальные метры станции), реквизит, кастрюли и пламя, путь кота, поднос, раковина, лужи, стол, частицы, реакции на события в `onEvent`.
- `cutboard.js` — `CutBoardView`, доска крупным планом. Куски из `CutBody.contour()` склеиваются в одну геометрию (`mergeGeometries`; во время реза — не чаще раза в ~70 мс). Один шейдер продукта через `onBeforeCompile` рисует мякоть, желток и семечки по координатам внутри исходного продукта. Маска чистки передаётся как `DataTexture`. Нож и рука следуют за мышью, есть подсказка-стрелка.
- `bowl3d.js` — `BowlView`: содержимое миски кучками (`InstancedMesh`), которые расходятся при перемешивании; в руке ложка, банка, майонез или солонка. `radio3d.js` — шкала, стрелка и ручка радио.
- `kitchen.js` — стены, мебель, станции (по `LAYOUT` из `src/game/layout.js`). `heroine.js`, `cat.js` — модели, построенные кодом без GLB, и позы `animateHeroine`/`animateCat`. `food.js` — блюда, посуда, инструменты, кэш материалов `m()`, `disposeGroup()`. `decor.js` — декор за баллы. `textures.js` — canvas-текстуры и логотип. `model-utils.js` — помощники для лепки. `board.js` — доска классического режима.

## 3. Архитектура в одном абзаце

Логика дня живёт в `KitchenSession`, это чистый JS без DOM и three.js. Время продвигается только через `update(dt)`
фиксированными подшагами по 0,05 с (не больше 0,25 с за кадр). Вся случайность идёт от `seed`, поэтому тесты и
`pacing-sim` детерминированы и управляют игрой через тот же API, что и игрок. Ввод из `main.js` превращается
в вызовы методов сессии. Сессия ничего не знает о показе: она складывает события в `outbox` через `_emit(type, data)`,
а `main.js` каждый кадр забирает их через `drain()` и раздаёт сцене, интерфейсу и звуку. View и UI каждый кадр сами
читают состояние сессии и не начисляют ни продуктов, ни баллов: интерфейс не владеет игровым состоянием. Игровые
числа лежат в `data.js` (`CAMPAIGN`, `PRODUCTS`, `RECIPES`, `DAYS`), координаты — в `layout.js`, тексты книги —
в `lessons.js` и `feed-data.js`.

```
ввод (main.js): мышь → view.pickLocal() → локальные метры станции; клавиши; клики по доку
        │  act('имяМетода', …args)   /   session.pointer('down'|'move'|'up', x, z)
        ▼
KitchenSession  (session.js + st-board/bowl/tray/home/phone/extra/radio.js)  ← data.js, layout.js
   update(dt): ходьба → действие → доска → удержания → кран → плита → духовка → доставка → кот → расписание
   _emit(type, data) → outbox
        │  main.js, каждый кадр: for (const e of session.drain()) dispatch(e)
        ├─► CampaignView.onEvent(e);  view.update(session, dt)   — three.js, читает состояние
        ├─► CampaignUI.onEvent(e, s); ui.render(session, dt)     — DOM, читает состояние
        ├─► Sound.play(SOUND_OF[e.type]);  RadioMusic.sync(session.radioTuning())
        └─► SaveStore: итог дня, покупка декора, любимая волна радио
```

Оговорки, которые стоит знать заранее (подробнее в п. 5):
- `KitchenSession` — один большой объект, у его прототипа 243 метода.
- `main.js` местами пишет в сессию напрямую: `startPractice`, `showFinal`, кнопки `?dev`.
- Кампания рисуется поверх сцены классического режима: `scene.js` строит и прячет доску и кольца 0.3.1, `kitchen.js` строит кухню по `LAYOUT`, а логика кампании работает по `CLAYOUT`.

## 4. Как устроены главные механики

- **Нож по сетке** (`raster-cut.js`, `st-board.js`). `boardSelect` кладёт на доску `CutBody` — сразу всю порцию, копии лежат рядом. `_boardPointer` поворачивает точку мыши в систему продукта на угол доски, затем `_knifePointer` на каждом движении с зажатой кнопкой вызывает `cutSegment(предыдущая, текущая)`. Поэтому косой росчерк даёт косые куски, дрожь руки — кривые, а зигзаг-«рубка» режет каждым взмахом. После разреза `_afterKnife` осыпает крошки (меньше 12 мм² или тоньше 1,5 мм). Качество считает `boardQuality` → `rasterQuality`: кусок засчитывается, если √площади лежит в пределах 0,65–1,45 размера кубика из рецепта (1 см для оливье, 2,5 см для канапе) и вытянутость не больше 2. Краевые обрезки прощаются в пределах 10 % (для яйца — 14 %).
- **Поворот доски A/D** (`main.js` + `st-board.js`). Короткое нажатие (до 180 мс) вызывает `boardTurn(dir)`: целевой угол сдвигается на четверть оборота, и `_updateBoard(h)` плавно доворачивает доску. Удержание каждый кадр вызывает `boardSpin(dir, dt)` — вращение на любой угол. `R` — то же, что D.
- **Чистка** (`coverage.js` + `st-board.js`). Для шага `peel` строится `_peelMask`: `CoverageMask` с эллиптической зоной на каждый продукт. `_peelPointer` проводит `strokeLine(..., { spread: false })`, поэтому снятая полоса не зависит от скорости мыши. При покрытии от 86 % срабатывает `_peelComplete`: шаг закрыт, и сразу открывается нарезка. Горячее не чистится — проверку делает `_hotBlock`.
- **Миска** (`st-bowl.js`). `bowlPick` даёт в руку банку (`PourTracker`: порции начисляются за путь руки над миской, горошек засчитывается сам при достижении нормы) или майонез (выдавливание засчитывается при отпускании; меньше `light` — это «поменьше майонеза» для гостей). `seasonPick` даёт солонку или перечницу: щепотка — это короткий клик над миской или взмах вниз-вверх (`ShakeTracker`). Перемешивание — `Stirrer`, нужно 4 оборота ложкой. Если начать мешать после соли, вызывается `seasonDone`. Фазы вкуса задаёт `seasonState`: `locked → spice → mixing → taste → done`. Пробовать (`seasonTaste`) можно только после перемешивания. Если досолить в фазе пробы, `unmixed` требует ещё один оборот (`_restir`). Пересол спасает `seasonDilute` — «досыпать картошки»: −1 щепотка соли и перца, и в миске видно картошку. Итог даёт `seasonQuality`; затем `_bowlFinish` отправляет салат на оценку, а начинку — на рабочую тарелку.
- **Плита с крутилками** (`st-home.js`). `placePot(burner, stepKey, heat = 6)` ставит кастрюлю. `setHeat(i, 0…9)` вызывается из перетаскивания крутилки в доке (`_bindPanel` в `campaign-ui.js`, 30° на деление) или кнопками −/+. `_updateStove(h)` моделирует воду: `T += (heatRate·огонь − loss·(T−20))·h`, кипение начинается с 99,5 °C, время кипения копится в `cooked`. Если огонь ≥ 7 держится дольше 8 с кипения, начинается `_startOverflow`; спасает `reduceHeat` или поворот крутилки ниже 6, иначе на полу лужа, штраф и −15 к подготовке. `_potEta` считает готовность аналитически: нагрев до кипения по логарифмической формуле плюс оставшееся время варки. На огне 2 и ниже вода не закипает.
- **Остудить под краном** (`st-extra.js` + `st-home.js`). После `takePot` продукт горячий 25 с (`hot[product]`). `coolPick(product)` кладёт его в раковину. `_sinkPointer` запоминает нажатие над раковиной, а `_updateSinkCool(h)` копит время, пока кнопка зажата; через 2,5 с продукт остыл. `coolProduct` — кнопочный вариант для тестов.
- **Радио** (`st-radio.js`, `radio-music.js`, `radio3d.js`). Частоту меняют три способа: круговой жест по ручке (`_radioPointer` → `turnKnob`), колесо мыши (`tuneRadio`) и кнопки ◀ ▶ (`seekRadio`). `radioMix` раскладывает приём на музыку и шум по силе сигнала. Сломанное радио чинится удержанием ручки (`setHold('radio')`). `main.js` каждый кадр отдаёт `session.radioTuning()` в `RadioMusic.sync`, а та синтезирует ноты из `radio-scores.js`. Любимая волна сохраняется.
- **Телефон и лента «Андрея»** (`st-phone.js`, `phone.js`, `feed-data.js`, `feed-art.js`). `_initFeed` показывает посты прошлых дней прочитанными, а посты текущего дня кладёт в очередь. `_updateFeed` выпускает их по игровым секундам (часы телефона: 14:00 + `at` минут). `feedItems()` собирает ленту из постов друзей и фото героини (`postPhoto` начисляет баллы), `likePost` ставит лайк. Картинки к постам — SVG по ключу `art`. В телефоне также банк (баллы, `buyDecor`) и таймеры (`setKitchenTimer`).
- **Кот** (`st-extra.js`, `st-home.js`, вид — `campaign-view.js`). Голод растёт: 0,42 в секунду, в первый день 0,3. С 50 приходит предупреждение. С 70, если на доске лежит соблазнительный продукт, начинается `_startCatTheft`: уведомление с таймером на 8–12 с, игрок отвечает `shoo()`. Не успел — `_stealFromBoard` уносит самый крупный кусок, и нужна `takeReplacement`. Сытый кот (`feedCat`) спит, и сценарные кражи из `DAYS` не случаются. В день 6 кот может опрокинуть компот (`_startSpillWarn`): получится лужа, которую надо вытереть, и пока она есть, через неё не пройти (`nav.setDynamic`).
- **Доставка** (`st-phone.js`, `st-home.js`). `draftSet` заполняет корзину, `confirmOrder(mode)` оформляет заказ: экспресс за 199 ₽ (20–30 с), обычная за 79 ₽ (45–75 с) или «сходить самой» (бесплатно, но 35 с героини нет на кухне). Проверяется бюджет дня; баллами можно оплатить до 50 %, кешбэк 5 %. `_updateDelivery` переключает статусы «принят → собирают → в пути → у двери». `collectOrder` уводит героиню к двери, `_deliveryReturned` ставит пакет, `unpack(i, 'fridge'|'pantry')` раскладывает продукты в запасы.
- **Оценка блюда и дня** (`scoring.js`, `session.js`, `st-extra.js`). `_finishDish(parts, notes)` вызывает `dishScore`: подготовка 0,30, состав 0,20, сборка 0,20, вкус 0,15, пожелания 0,15; неприменимые части не дают бесплатных баллов. `finishDay()` собирает `orderScore()` (100 минус разовые происшествия и неубранное), `paceScore()` (100 в пределах ориентира `targetMinutes`, дальше вниз до 40) и `dayScore` с весами 0,75 / 0,15 / 0,10. Звёзды даются за 55, 75 и 90 баллов, медали считает `_medals`. `recordDay` хранит лучший и последний результат.

## 5. Куда смотреть ревьюеру в первую очередь

## 6. Известные ограничения и решения владельца

Решения владельца — не баги, их стоит учитывать при ревью (`.planning/*/task_plan.md`, `CHANGELOG.md`):
- «Всё руками, как в жизни», но реализм должен прощать ошибки. Интерактив вместо «клик → действие» (`design/gdd/interaction-spec.md`).
- Нож режет по растровой маске: косые и кривые куски — это намеренно. Мелкий кубик режут «рубкой». Доску поворачивают только A/D: короткое нажатие — 90°, удержание — свободно.
- Порядок вкуса: посолить → перемешать → попробовать; досолила — ещё оборот. «Разбавить водой» убрано, вместо него «досыпать картошки».
- Огурцы двух видов: солёный (`pickle`) в оливье, свежий (`cucumber`) в крабовом и канапе. Чистка картофеля и яиц — отдельный шаг, не зависящий от скорости мыши. Остужать под краном — руками.
- Музыка радио генерируется кодом из мелодий в общественном достоянии, чтобы в Steam не было вопросов с правами.
- «Андрей» — мессенджер внутри игры (как MAX, только «Андрей»): чаты, каналы, живая лента; у мессенджера есть свой официальный канал «Андрей». Названия и логотипы настоящих мессенджеров не используем.
- Канапе — «как в жизни»: стопка на хлебе снизу вверх, потом шпажка сверху (0.7.1).
- Публичные ссылки — только на нейтральную сборку (`VITE_NEUTRAL=1`). Логический контур моркови не меняется: её узнаваемость дают шейдером.
- Режим стрима выключен в этом билде (`STREAM_ENABLED = false`), код оставлен. Таймера-проигрыша нет: день завершается кнопкой, когда все блюда готовы. Если закрыть игру посреди дня, этот день начнётся заново.
- Режим работы: автономные этапы, коммит и push в рабочую ветку после каждого этапа (Conventional Commits).

Известные ограничения (`docs/QA_v06.md` и код):
- Героиня и кот построены кодом. В крупном плане у героини видны только кисти, рук нет. GLB художника ещё нет (`docs/asset-contract.md`).
- На финальное качество «руками» доведён в первую очередь день 1 (и канапе дня 6 в последнем коммите). В днях 2–7 остались кнопки и прежние жесты — статусы по станциям в `interaction-spec.md`. Сценарии дней 2–7 в `campaign-e2e.mjs` обновлены лишь частично.
- Вызовов отрисовки ~490 при бюджете 250 (см. п. 5). Проверки идут в контейнере без GPU (SwiftShader, 1–3 FPS); Mac и Windows собирает CI, а живую проверку на железе делает владелец.
- Замена куска от кота может уйти под карточки уведомлений справа вверху. Лайки и прочитанное в ленте не переносятся на следующий день. В опросе в ленте нельзя проголосовать.
- Устаревшие тексты: `README.md` (там версия 0.5.0 и поворот на R), описание в `package.json` и заголовок `data.js` («0.4»), `assets/README.md` (ссылается на несуществующий `npm run models:sync`).
